Enrôlement wallet OpenID4VCI

Un utilisateur déjà connecté à l'application y enrôle son wallet : l'application lui émet, par OpenID4VCI (grant pré-autorisé, endpoints obligatoires, plus le nonce endpoint optionnel), une attestation contenant un identifiant de compte. Cette attestation servira ensuite à se connecter par OpenID4VP. Voir le glossaire.

Glossaire

OpenID4VCI
OpenID for Verifiable Credential Issuance. Protocole, bâti sur OAuth 2.0, par lequel un émetteur dépose une attestation dans un wallet. Référence
OpenID4VP
OpenID for Verifiable Presentations. Protocole par lequel un wallet présente une attestation à un verifier. Référence
Wallet
Application de l'utilisateur qui stocke ses attestations et les clés qui y sont liées.
Émetteur (Credential Issuer)
Celui qui signe et délivre l'attestation. Ici, l'application.
Authorization Server (AS)
Serveur OAuth qui délivre l'access token. Peut être l'émetteur lui-même.
Verifier
Celui qui demande et vérifie une présentation. Ici, l'application au moment de la connexion.
Attestation (Verifiable Credential)
Ensemble d'informations (claims) signé par un émetteur, vérifiable par n'importe qui avec sa clé publique.
Claim
Une information portée par l'attestation, par exemple account_id.
SD-JWT VC
Format d'attestation basé sur JWT où chaque claim peut être divulgué ou non (Selective Disclosure). Référence
Disclosure
Morceau d'un SD-JWT, après un ~, qui révèle un claim. Le wallet n'envoie que celles qu'il veut montrer. Référence
mdoc
Autre format d'attestation (ISO 18013-5, permis mobile), encodé en CBOR.
Credential Offer
Message de l'émetteur au wallet qui annonce une attestation disponible et comment l'obtenir. Référence
Credential configuration
Une entrée du catalogue de l'émetteur : format, type et règles d'une attestation.
vct
Verifiable Credential Type : identifiant du type d'une attestation SD-JWT VC.
Grant
Terme OAuth : la façon d'obtenir un access token (code d'autorisation, pré-autorisé…). Référence
Pre-authorized code
Code fourni dans l'offre quand l'utilisateur est déjà authentifié. Échangé directement contre un access token. Référence
tx_code
Code de transaction optionnel envoyé par un autre canal (SMS…). Protège le pre-authorized code s'il est intercepté. Référence
Access token
Jeton temporaire qui autorise le wallet à appeler le credential endpoint. Référence
Endpoint
URL d'un serveur qui reçoit un type de requête précis (token, credential…).
Metadata / .well-known
Document JSON publié à une adresse standard, qui décrit les endpoints et capacités d'un serveur. Référence
JWT
JSON Web Token : header, payload et signature encodés en base64url, séparés par des points. Référence
JWK
JSON Web Key : une clé cryptographique écrite en JSON. Référence
ES256
Signature ECDSA sur la courbe P-256 avec SHA-256. Référence
Proof JWT (preuve de possession)
JWT signé par le wallet qui prouve qu'il détient la clé privée à lier à l'attestation. Référence
Holder binding / cnf
Lien entre l'attestation et une clé du wallet, inscrit dans le claim cnf. Une copie de l'attestation est inutile sans la clé. Référence
Nonce / c_nonce
Valeur aléatoire à usage unique à signer, pour prouver que la signature est récente et empêcher le rejeu. Référence
KB-JWT
Key Binding JWT : ajouté à la fin d'un SD-JWT présenté, signé par la clé cnf avec le nonce du verifier. Référence
DCQL
Digital Credentials Query Language : format JSON de la requête OpenID4VP qui décrit les attestations voulues. Référence
PKCE, PAR, DPoP
Protections OAuth optionnelles ici, absentes de ce flux minimal : lien code/wallet, requête poussée côté serveur, jeton lié à une clé. RFC 7636 RFC 9126 RFC 9449
